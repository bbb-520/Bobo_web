# Bobo_web

`BoboWeb` 是 Bobo4J（AgentDemo 后端：Spring Boot WebFlux + Spring AI）的 React / Vite 前端。

浏览器端只使用**同源路径**访问后端：开发、生产环境都通过 Node 服务或 Vite 代理把 `/api/` 转发给 Java 后端，登录 Cookie 与 SSE 流在两个环境下行为一致。

2026-10-13 的上线记录为历史状态；2026-10-18 的分类确认修复仅在本地验证并提交源码，尚未部署服务器。

## 五种聊天模式与图片生成（2026-10-13）

本次补全纯文字生图和独立图片任务入口。默认使用“智能聊天”，明确指令如“帮我生成一张图片：海边日落”会推荐图片生成，确认后才创建任务；回复上方标注本次实际模式。询问原理、教程、翻译、提示词写作和否定语句保留为问答，模糊创作需求可手动选择图片生成。

| 模式 | 输入与用途 |
| --- | --- |
| 智能聊天 | 文字、图片、文件或混合附件；自动选择问答类型，识别为创作后需本次确认 |
| 文本聊天 | 纯文字，不沿用旧图片或文件；识别为创作后确认转为纯文字生图 |
| 图片多模态 | 识别、理解、比较图片，最多 3 张，支持沿用图片追问 |
| 文件多模态 | 文件概要、检索、问答，可搭配图片，支持沿用文件会话 |
| 图片生成 | 纯文字生成一张图片，或上传一张参考图编辑；不接收文档或多张参考图 |

普通附件最多 8 个，图片最多 3 张、每张 20 MiB，文件每份 100 MiB；扫描 PDF 暂不支持 OCR。参考图片建议使用 JPEG/PNG/WebP/GIF；资产上传接口不支持 BMP/TIFF，需先转换格式。

图片生成先记录本次用户确认和客户端请求 UUID，再创建服务端任务；刷新、响应丢失和重试均核对同一请求，不另建收费任务。已受理后显示独立任务卡，输入框解除本页等待。上传及受理等待有 2 分钟上限，上传失败需重新选择文件；过期或不可用参考图返回明确的 400。任务查询每次最多等待 15 秒，列表暂时不可用时仍继续查询本地已受理任务。失败终态及实际模式在刷新后保留。

停止按钮停止本页等待；已受理的供应商任务仍继续，完成后可刷新查看，也会按实际结果结算。停止意图会持久化，刷新只查询，不补发未受理任务。免费 100 万 Token 仍通用于所有模型，图片优先实际 Token，无 Token 回执按现有价格折算；查询和幂等重放不产生新消费。

本次 15 组前端测试脚本及生产构建通过，其中模式路由 35 项、图片请求恢复 13 项。已部署至 `https://www.boboo.xin/`，全部静态资源与测试产物一致；真实纯文字生图与参考图编辑均成功返回 OSS 图片，幂等重放不重复生成或扣费。可按 Ctrl+F5 更新页面后，在默认智能聊天输入“帮我生成一张图片：海边日落”，或直接选择图片生成模式。

线上回归的实际范围：文字聊天、纯图片理解与追问、文档上传/索引/摘要、重排序检索及公开纯文档概述均有成功回执。完整文档问答与图片文档混合问答**本轮未全部通过验收**：曾发生向量/重排序连接中断，以及答案评估不可用。前两次未知调用已自动进入 ABANDONED 并释放占用；评估失败进入 FAILED，未发布未经核验的答案。没有将未知用量改为零，也未用重复派发绕过对账。5 个隔离测试账户均已禁用、会话数为 0、现金余额/预留为 0、无账户占用，失败记录保留在发布目录。此限制属于现有文档模型链路的可用性，本次图片生成与模式划分未声称修复其全部外部调用问题。

## 技术栈

- React 18 + TypeScript 5.6 + Vite 5
- 3D 与动效：three / @react-three/fiber / @react-three/drei、gsap、motion、ogl
- 生产运行时：Node 22（`server.mjs`，纯标准库，零生产依赖）

## 开发

```bash
npm ci
npm run typecheck
```

开发有两种方式：

```bash
npm run dev:vite   # Vite 开发服务器（HMR），127.0.0.1:5173，/api 代理到后端
npm run dev        # Node 静态服务，需先 npm run build，行为与生产一致
```

Vite 开发服务器把 `/api` 代理到 `BACKEND_URL`（默认 `http://localhost:18000`，即后端网关）。SSE 由 `http-proxy` 直接透传，无需额外配置。

## 构建

```bash
npm run build     # tsc -b && vite build
```

构建产物位于 `dist/`。

## 生产运行

### 方式一：Node 服务

`server.mjs` 同时提供静态资源、`/health` 健康检查和 `/api/` 反向代理：

```bash
PORT=5173 BACKEND_URL=http://127.0.0.1:18000 STATIC_DIR=dist node server.mjs
```

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `5173` | 监听端口（绑定 `0.0.0.0`） |
| `BACKEND_URL` | `http://localhost:18000` | 后端网关地址 |
| `STATIC_DIR` | `dist` | 静态资源目录 |

要点：

- 静态资源做路径穿越校验；带哈希的静态文件长缓存，`index.html` 不缓存。
- `/api/` 请求流式转发，`AbortController` 在客户端断开时同步取消上游请求。
- 请求体超过 100 MiB 直接返回 `413`（multipart 额外放宽 1 MiB 头部开销）。

### 方式二：Docker / Compose

以下部署文件完整保留在本地，按核心源码发布范围从 Git 取消跟踪；公开仓库克隆后使用上方 Node 方式，不能直接执行此本地 Compose 入口。

```bash
docker compose up --build
```

- `Dockerfile` 为多阶段构建：`node:22-alpine` 构建 `dist/`，运行阶段只拷贝 `dist/`、`server.mjs`、`upload-stream.mjs` 与 `package.json`，以非 root 用户运行，并内置 `/health` 健康检查。
- `docker-compose.yml` 通过 `include` 把后端与基础设施栈（gateway、auth、chat、media、content、orchestrator、rag、nacos 等）合并进同一 Project，一条命令启动完整系统。
- 只有 `agent-gateway`（`GATEWAY_PORT`，默认 `18000`）与 `agent-web`（`WEB_PORT`，默认 `5173`）对外暴露端口，其余服务走 Compose 内网。

### 方式三：Nginx

1. 执行 `npm run build`。
2. 将 `dist/` 内容复制到 `/var/www/AgentWebDemo/`。
3. Nginx 以该目录作为 `root`，并把 `/api/` 代理到后端。

Nginx 必须关闭 `/api/` 的响应缓冲（`proxy_buffering off;`），否则 SSE 会等到整段响应结束才显示内容。

## 接口一览

前端默认 `baseUrl` 为空（同源）。所有写操作都会先请求 `GET /api/auth/csrf` 取得令牌，再以 `X-XSRF-TOKEN` 头提交，并始终携带 `credentials: 'include'`（HttpOnly 登录 Cookie）。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/chat` | SSE 流式对话 |
| `POST` | `/api/chat/image-intent` | 图片上下文意图分类，返回 `GENERATE` / `REMIX` / `DESCRIBE`；无法确定时返回可重试错误 |

## 安全

- 登录态使用 HttpOnly Cookie，写操作走 CSRF 双提交（`X-XSRF-TOKEN`），`fetch` 统一 `credentials: 'include'`。
- 密钥与凭据不入库：`.env`、`secrets/`、`*.pem`、`.docker-work/` 已在 `.gitignore` 中排除；本地保留的 `.dockerignore` 及 `.env.example` 分别提供容器排除与配置示例，不随核心源码发布。
- 管理端敏感操作（授予 `SUPER_ADMIN` 等）要求二次输入密码并填写操作原因，全部写入授权审计。
